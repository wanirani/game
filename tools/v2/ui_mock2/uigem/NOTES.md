# 2차 시안 uigem — 「세공한 유리」 (보석과 은세공)

2026-11-17 · `docs/v2/UI_ROUND2.md` 에 들어갈 절. 시안은 `tools/v2/ui_mock2/uigem/` 의 눌리는 웹 페이지이고, 게임 코드는 건드리지 않았다.

## 1. 생각 (두 줄)

- 버튼은 **배경이 비치는 밤색 유리 원판**이고, 값비싼 느낌은 넓이가 아니라 **가장자리와 그림**에서 낸다: 가는 백금 테, 테 안쪽의 구슬 줄(밀그레인), 유리 밑의 가는 물결 무늬(시계 문자판의 기요셰), 붉은 보석 하나.
- 아이콘은 기호가 아니라 **상아에 새긴 작은 조각**이다 — 게임 속 카엘 3D 모델이 실제로 그 동작(베기 · 뛰기 · 내달리기 · 막기)을 하는 모습을 그대로 부조로 구웠다.

## 2. 재질과 색

| 것 | 재질 | 값 |
|---|---|---|
| 버튼 원판 | 밤색 유리. 가운데는 옅고(검정 27 %) 테 쪽으로 짙어진다(64 %) → 두꺼운 렌즈처럼 보이고 가운데로 배경이 비친다. 위쪽에 반사광 초승달, 아래쪽에 옅은 푸른 안빛 | `rgba(9,11,24,.27→.64)` |
| 테 | 백금. 대각선으로 밝음–어둠–밝음이 지나가는 금속 반사 + 안쪽에 지름 1 px 구슬 줄 + 안팎 어두운 실선(밝은 배경에서 테가 묻히지 않게) | `#ffffff → #6f7789 → #e6eaf2` |
| 유리 밑 무늬 | 기요셰(겹친 원 30개의 로제트), 흰색 13 % | 공격 버튼은 더 촘촘한 44개 |
| 강조 | 루비 카보숑(둥근 붉은 보석): 공격 버튼 꼭대기, 궁극기, 켜진 버튼, 보스 막대 머리, 미니맵 북쪽, 선택된 탭, 대화 넘김 표시. **이것 말고 색은 쓰지 않는다** | `#ffc9c6 → #ff4a5c → #c8142e → #7a0a1e` |
| 아이콘 | 상아 부조: 밝은 상아 면 + 짙은 호박색 음각 선 + 윗왼쪽 빛의 볼록 음영 + 짙은 윤곽과 그늘 | 면 `#efe5cf`, 음각 `#5a4636` |
| 체력 | 양 끝이 뾰족한 백금 틀 안의 루비 유리 막대(윗면 반사 줄), 뒤따르는 잔량은 상아색, 25 % 눈금 | |
| 기력 | 같은 틀, 월장석(푸른 흰색) | `#ffffff → #c7d6ff → #7f9be6` |
| 판(대화 · 메뉴) | 밤색 유리판(74–82 %) + 은선 두 겹 + 네 모서리 꺾쇠 장식 + 윗변 반사광 | 대화 상자 모서리만 루비 |
| 등급 | 칸 아래에서 올라오는 빛 + 안쪽 실선: 초록 · 파랑 · 보라 | |
| 글자색 | 상아 `#f6efdf`, 흐린 글자 68 %, 작은 제목은 옅은 금 `#ecd49a` | |

상태(버튼): 준비됨 = 그대로 / **눌림** = 0.93배 + 유리 안에서 흰 빛 + 바깥 고리 / **재사용 대기** = 유리가 어두워지고 그림이 흐려지며 **테가 시계 방향으로 다시 차오른다**(가운데 남은 초) / **잠김** = 테 · 그림이 흐려지고 자물쇠 / **켜짐**(조준 · 막기 유지) = 루비빛 유리 + 작은 보석 / **궁극기** = 테가 루비색으로 차오르고, 다 차면 붉은 달빛이 번진다.

실시간 흐림(backdrop blur)은 **어디에도 쓰지 않았다**. 메뉴 배경만 "멈춘 화면을 한 번 흐리게 구운 그림"이고(실시간 아님), 흐림 없이 어둡게만 한 판도 찍었다(`*_menu_noblur.png`, `?noblur=1`) — 유리판이 74 % 이상 불투명해서 흐림 없이도 읽힌다.

## 3. 글자

새 글꼴 없이 **지금 들어 있는 것만** 쓴다(`assets/fonts`, 첫 화면 예산 변화 없음).

| 쓰임 | 글꼴 | 까닭 |
|---|---|---|
| 이름 · 제목 · 보스 이름 · 임무 이름 · 아이템 이름 · 버튼 글자 | **Hahmlet** 700–800, 자간 넓게 | 도톰한 명조가 은세공 · 상아와 같은 "새긴 글자" 느낌 |
| 숫자 전부 (체력 · 레벨 · 수량 · 피해 · 재사용 초 · 돈) | **Cinzel** 700–900 | 로마 비문체 숫자 — 보석 세공의 각인처럼 보이고, 굵기 대비가 커서 작아도 또렷하다 |
| 본문 · 설명 · 대화 · 작은 이름표 | **Noto Sans KR** 400–600 | 긴 한국어 문장은 고딕이 가장 잘 읽힌다 |

- Hahmlet 은 600 이상만 들어 있어 긴 본문에는 쓰지 않았다. 대화까지 명조로 가고 싶다면 가는 굵기가 있는 **마루 부리(MaruBuri, SIL OFL 1.1)** 를 대화 전용으로 나중에 받게 하면 된다(선택).
- 가장 작은 글자: 폴드 10.5 px(체력 최대값), 휴대폰 10 px(「치명」 표시). 대화 본문 20 / 15 px.
- 시안 문구는 게임 문구가 아니다. 실제로 넣을 때는 글꼴 부분집합 검사(`tools/fonts/build_fonts.py --check`)를 거쳐야 한다.

## 5. 게임 캔버스에서 그리는 법

HUD 는 WebGL 장면 위의 2D 캔버스다. v1 규칙(매 프레임 그라데이션 금지)에 맞춰 **무거운 것은 전부 미리 굽고**, 프레임마다 하는 일은 `drawImage` 와 호 몇 개뿐이다.

| 것 | 미리 구운 그림 (시작할 때 한 번, 오프스크린 캔버스) | 프레임마다 그리는 것 |
|---|---|---|
| 버튼 원판 | 종류(공격 · 보통 · 작은 것 · 궁극기) × 상태(보통 · 눌림 · 대기 · 잠김 · 켜짐 · 다 참) ≈ 12장: 방사 그라데이션 3겹 + 기요셰(원 30개 선) + 테(선형 그라데이션 선) + 밀그레인(둥근 끝 점선 `setLineDash`) + 보석 | `drawImage` 1번 (+ 눌림은 0.93배) |
| 아이콘 | 256 px 그림 20장을 한 장으로 묶음. 짙은 그늘(윤곽 번짐)은 **그림에 미리 구워 넣는다** — 시안의 CSS drop-shadow 에 해당 | `drawImage` 1번 |
| 재사용 대기 | 어두운 원판 · 흐린 테는 구운 그림 | 차오르는 테 = `arc` 선 1개, 남은 초 = 숫자 그림 |
| 궁극기 충전 | 붉은 빛무리 그림 1장 | 루비색 `arc` 선 1개, 다 차면 빛무리를 `globalAlpha` 로 숨쉬게 |
| 스틱 | 바탕 원판 1장 + 손잡이(유리 구슬) 1장 | `drawImage` 2번 |
| 체력 · 기력 · 보스 막대 | 뾰족한 틀(3칸 늘리기) + 루비/월장석 띠(1×높이 그라데이션 띠) | 길이만큼 자르는 `clip` + 띠 `drawImage`, 잔량 띠 1번 더 |
| 미니맵 | 유리판 + 눈금 테 1장, 방 윤곽은 방이 바뀔 때만 다시 구움 | 적 · 영웅 점 |
| 임무 줄 · 획득 알림 · 이름표 | 글자까지 통째로 구움(내용이 바뀔 때만) | `drawImage` 1번 |
| 피해 숫자 | 숫자 0–9 · 「-」 · 「치명」을 세 가지 양식(보통 · 치명 · 받은 피해)으로 윤곽째 구운 묶음 | 숫자마다 `drawImage` (글자 그림자 · 테두리를 매번 그리지 않는다) |
| 판(대화 · 메뉴) | 9칸 늘리기 그림: 유리판 + 은선 두 겹 + 모서리 장식, 칸(등급 5종) · 탭 2종 · 버튼 3종 | `drawImage` 9칸 + 글자 |
| 메뉴 배경 | 메뉴를 여는 순간 멈춘 화면을 1/8 로 줄였다 늘려 한 번 흐림(실시간 아님). 못 쓰면 어둡게만 | `drawImage` 1번 |
| 초상(대화) | 흉상 그림 + 아치 액자 그림 | `drawImage` 2번 |

전투 화면 한 프레임: `drawImage` 약 35번 + 호 2–3개 + 자르기 3번. 흐림 · 그림자 · 그라데이션 생성은 0.
구운 그림은 기기 배율에 맞춰 한 번만 만든다(폴드 2.6배에서 버튼 12장 ≈ 2 MB 메모리). 내려받는 것은 아이콘 묶음뿐(지금 321 KB, 192 px 로 줄이면 약 180 KB).

## 7. 만드는 비용

1차 「달빛 유리」를 1 로 보면 약 **1.5배** (어림).

- `src/core/touchpad.js`: 배치 · 판정 · 편집기는 그대로. 테 그림 8장 대신 **굽는 모듈 하나**(유리 · 테 · 무늬 · 보석 · 상태, 약 250–300줄)와 그리는 함수 교체, 재사용 · 충전 호 추가.
- `src/render/hud.js`: 어느 시안이든 새로 쓴다(막대 · 미니맵 · 임무 · 보스 · 알림 · 숫자 묶음). 이 시안은 뾰족 막대 · 숫자 묶음 굽기가 더 든다.
- 메뉴(`src/scenes/menu/` 16파일): 밝은 글자 그대로라 `ui.js` 의 색 · 판 · 버튼 · 막대를 9칸 그림으로 바꾸면 대부분 따라온다. 색을 직접 쓴 99곳 손질. 다시 칠하기 약 80 %.
- 아이콘: 카엘 한 벌 20개는 끝났다. **영웅이 늘 때마다 기술 아이콘 3–4개**가 필요하다 — 그 영웅의 3D 모델 동작 렌더가 있으면 1개 10–15분(자세 고르기 + 궤적 얹기), 없으면 v1 기술 그림(`assets/icons/skills` 89장)을 같은 필터에 넣는 것이 대안. v1 아이템 그림 228장은 **가방 칸에 그대로 쓴다**(시안이 그렇게 했다).
- 글꼴: 변화 없음. 내려받기: 아이콘 묶음 180–321 KB.

## 8. 약한 점

1. **밝은 불빛 위에서는 유리만으로 못 버틴다**(유리만 1.7). 그림의 짙은 윤곽 · 그늘에 기대고 있고, 흰 불빛 위의 작은 회색 글자(직업 이름, 체력 최대값)는 흐리다. 화면 위쪽 그늘(시안에 있음)을 없애면 더 나빠진다.
2. **동작 아이콘끼리 닮았다.** 같은 인물의 자세라 48 px 에서는 점프 · 대시 · 세 갈래 베기가 궤적으로만 구별된다. 이름표가 없어 처음 하는 사람은 눌러 봐야 안다.
3. **아이콘이 카엘 한 명의 모델에 매여 있다.** 다른 영웅은 모델이 생길 때까지 기술 아이콘을 만들 수 없다(또는 v1 그림으로 대신).
4. 조준 · 지도는 평평한 벡터라 다른 아이콘보다 덜 세밀하고, 사물 아이콘은 128 px 짜리 v1 그림을 키운 것이라 크게 보면 무르다(버튼 크기에서는 괜찮다). 유료 생성이 풀리면 이 둘과 공격 아이콘(가장 크게 보인다)부터 다시 그리는 것이 좋다.
5. 은 · 상아 · 루비는 차갑고 격식 있는 쪽이다. 가죽 · 뼈의 따뜻한 수렵 장비와 온도가 다르고, 1차 「은세공」처럼 옛 고딕 분위기로 읽힐 수 있다.
6. 휴대폰에서는 버튼 10개가 오른쪽 1/3 을 채운다(32 %). 생김새로는 못 줄인다(1차와 같은 문제).
7. 재지 않은 것: 실제 폴드 · 실제 손가락, 캔버스로 옮겼을 때의 프레임 시간, 색각 보정. 헤드리스 Chromium 캡처만 봤다.
