## 0. 한눈에

- **투영은 원근(소실점 1개)으로 정했다.** 평행 투영도 같은 코드로 켜 볼 수 있게 해 두고(`&proj=oblique`) 둘을 찍어 비교했다 (§2).
- 세계는 **축에 나란한 판(slab) 목록**이다. 스테이지 한 개 = 저작 낱말 50–100 줄, 검증은 자동 (§1).
- 바닥·벽 무늬는 v1 타일 그림을 **가는 띠로 잘라** 아핀 변환으로 그린다 — 카메라가 돌지 않으므로 화면 한 줄이 깊이 하나라서 이음매 없는 원근 바닥이 된다 (§3).
- 영웅은 v1 채색 퍼펫, 적 2종은 v1 채색 레지스트리 그림을 **고치지 않고** 그대로 그린다 (§7).
- 봇이 가상 패드 입력만으로 구간을 끝까지 깬다: 폴드 41–49초, 휴대폰 45초, 쓰러짐 0 (§9).

## 1. 세계 모델과 저작 형식

좌표는 헌장 §4: `x` 좌우, `z` 깊이(안쪽 +), `y` 높이(위 +).

**판 = `{ x0,x1, z0,z1, top, kind, mat }`** — 바닥에서 윗면 `top` 까지 꽉 찬 상자.

| kind | 뜻 | 그리는 때 |
|---|---|---|
| `floor` | 걷는 바닥. 계단도 얇은 바닥 여러 장 | [A] 캐릭터보다 먼저, 높이가 낮은 것부터 |
| `block` | 바닥 위에 솟은 덩어리 (단상·상자·단상 계단) | [B] 캐릭터와 깊이 순으로 |
| `wall` | 오를 수 없는 벽 (건물·담) | [B] |

- 땅 높이 = 그 점을 덮는 판 가운데 가장 높은 `top`. 판이 없으면 −∞, `walk:false` 판과 벽은 걸을 수 없다.
- **구덩이** = 바닥에 뚫은 구멍 + 그 자리의 바닥판(`top = −230`). 구멍은 저작기가 사각형을 잘라서 만든다.
- **소품** = 그림 한 장(빌보드) + 선택으로 발 자리 막이(보이지 않는 block).
- **구간**(section) = 사각형 + 들어가는 점. 카메라 구도·되살아나는 자리·`teleport` 가 쓴다.

저작 낱말 (`StageBuilder`): `floor(x0,x1,z0,z1,top,mat,{holes,walk})` · `pit` · `block` · `wall(…,{deco,cutIn})` ·
`stairs({x0,x1,z0,z1,from,to,steps,axis,kind})` · `prop(kind,x,z,{block,light,hideIn})` · `spawn(kind,x,z,{group,y})` · `section(id,…)`.
SLICE0 전체(거리·모퉁이·골목·마당, 판 58장·소품 32개·적 17마리)가 `buildSlice0()` **65줄**이다. 예:

```js
b.floor(-400, 2880, 0, 330, 0, 'cobble', { holes: [[1500, 1680, 130, 260]] });   // 거리 + 구덩이 자리
b.pit(1500, 1680, 130, 260);
b.block(760, 1060, 140, 260, 72, 'stone');                                       // 돌 단상 300×120×72
b.stairs({ x0: 676, x1: 760, z0: 150, z1: 260, from: 0, to: 72, steps: 6, axis: 'x', kind: 'block' });
b.stairs({ x0: 1980, x1: 2400, z0: 560, z1: 760, from: 0, to: 96, steps: 8, axis: 'z' });   // 골목 오르막
b.prop('pillar', 430, 132, { block: [20, 13] });
```

빌드할 때 한 번 계산해 두는 것: 판마다 **보이는 옆면 조각**(이웃 판의 경계에서 잘라, 조각마다 바깥 이웃의 윗면까지만 내려감 —
그래서 옆면이 앞의 바닥을 덮어 그리는 일이 없다), 바닥의 (높이, 재질) 묶음, 소품의 땅 높이.

**자동 검증** `stage.validate()` (node 에서도 실행, 검사 스크립트가 부른다):
1. 판 크기 · 2. 걷는 바닥끼리 겹치는데 높이가 다르면 오류 · 3. 시작점에서 **걸어서만**(턱 ≤ 14) 모든 구간의 들어가는 점에 닿는가
(격자 20 px 채우기) · 4. 점프(턱 ≤ 128)까지 쓰면 모든 적 자리에 닿는가 · 5. 적 자리가 벽·구덩이 속이 아닌가 ·
6. 그리기 규칙 위반 알림 — 걷는 바닥보다 높은 `floor` 가 카메라 쪽에 붙어 있으면 뒤의 캐릭터를 가리지 못하므로 `block` 으로 쓰라고 한다.

## 2. 투영 — 원근으로 정한 까닭

카메라는 늘 +z 를 보고 **돌지 않는다**. 초점(땅 위 한 점) `cam.(x,y,z)`, 초점 거리 `f`, 눈 높이 `h`, 화면 배율 `zoom`.

```
s(z)    = zoom · f / (f + z − cam.z)                 초점 깊이에서 배율 = zoom
screenX = cx + (x − cam.x) · s
screenY = horizon + (h − (y − cam.y)) · s            horizon = footY − h·zoom,  footY = 화면 높이 × 0.72
```

세로선이 늘 세로로 남는 투영(건축 사진의 렌즈 시프트)이다. 값: 거리 `f 770`, 골목 `f 600`, 마당 `f 660`, `h ≈ 화면 높이 × 0.445`
(폴드 323), `zoom = 화면 높이 / 560`(폴드 1.3, 휴대폰 1.0 — 영웅이 화면 높이의 15 % 쯤).

**둘 다 해 봤다.** 같은 세계를 `&proj=oblique` 로 열면 평행 투영(`screenY = footY − (z − cam.z)·0.42 − y`, 깊이 1000 에 크기 −20 %)이다.
캡처 `90_oblique_street.png`, `91_oblique_alley.png` 와 `01_street.png`, `08_alley_stairs.png` 를 나란히 보면:

| | 평행(비스듬) | 원근 (채택) |
|---|---|---|
| 횡 구간 | 익숙한 벨트스크롤 화면. 깊이 260 이 화면 109 px | 영웅이 길 가운데 설 때 앞줄(z 0)은 1.07배, 뒷줄(z 260)은 0.79배로 보이고, 걸으면 앞쪽 가로등·울타리가 빨리 지나간다 |
| 종 구간 | 길이 위로만 흘러 **위에서 본 지도**처럼 보인다. 옆 벽은 거의 선 | 벽이 소실점으로 모이는 **복도**. 멀리 마당의 석상과 붉은 달이 처음부터 보인다 |
| 모퉁이 | 화면이 옆→위로 스크롤 방향만 바뀜 | 건물 사이로 골목 안이 들여다보이고, 카메라가 그 안으로 미끄러져 들어간다 |
| 바닥 무늬 | 그대로 붙이면 됨 | 띠로 잘라야 하지만 이음매 없이 된다 (§3) |

소유자가 고른 것이 "모든 곳에서 앞뒤로 움직인다"이고 종 구간이 "세계 안으로 들어가는" 느낌이어야 하므로, Canvas 2D 로도 원근이 되는 것을
확인한 뒤 원근으로 정했다. 평행 모드는 비교용으로만 남겼다(옆면·안개가 원근 기준이라 다듬지 않았다).

## 3. 그리는 순서와 가림

```
① 먼 배경   하늘 + 붉은 달과 성(v1 bg/s01_village) + 판이 없는 어두운 땅을 한 장에 구워 한 번에 (x 시차 4 %)
② [A] 바닥  높이가 낮은 묶음부터: 그 높이 판들의 옆면(구덩이 안벽·계단 챌면) → 윗면 합집합
③ 빛 웅덩이 가로등·횃불 아래 바닥에 더하기
④ [B] 깊이 정렬(먼 것부터): 솟은 판(키 = 뒤쪽 끝 z1) · 소품(z) · 캐릭터·탄(z) · 안개 판 2장
⑤ 공기 중 불티 → 타격 이펙트·숫자 → HUD
```

- **윗면 무늬**: 깊이를 화면 4 px(낮은 화질 9 px) 두께의 띠로 나눈다. 띠마다 ① 기본 변환에서 그 띠에 걸친 판들의 사다리꼴을 경로로
  만들고 ② `setTransform` 을 그 깊이의 배율로 바꾼 뒤 무늬(`createPattern`)로 채운다. 경로는 만들 때의 변환, 무늬는 채울 때의 변환을
  따르므로 가장자리는 정확한 사선이고 무늬는 세계에 붙는다 — `clip` 없이, 띠 하나에 채우기 한 번.
- **앞면**(화면과 나란한 면)은 직사각형 한 번. **큰 벽의 옆면**은 세로 띠(3 px, 낮은 화질 9 px) 직사각형 + 위아래 톱니를 덮는 그늘 띠.
- **안개·밤 빛깔은 타일에 미리 굽는다**: 재질 × 면(위·앞·옆) × 안개 8단계. 먼 단계일수록 타일도 작다(256 → 128 → 64 px, 밉맵 구실).
  덧칠(overdraw)이 없다.
- **가림**: [B] 의 정렬 키만으로 된다. 기둥(z 132) 뒤에 선 영웅(z 178)은 먼저 그려져 가려지고, 앞에 서면 나중에 그려진다. 단상 위에
  서면 단상(키 = 뒤끝 260)보다 나중. 구덩이에 빠지는 영웅은 앞 테두리 선 아래를 잘라(`clip` 사각형) 가린다.
- 걷지 않는 **화면 앞쪽 갓길**(z < 0)의 가로등·울타리·수레는 영웅 앞을 지나가는 가림막이다. 영웅을 덮을 때만 60 % 투명해진다
  (싸움이 가려지지 않게). 걷는 곳의 기둥은 그대로 가린다.
- **벽 자르기**: 마당에 들어서면 카메라와 영웅 사이에 놓이는 골목 벽(`cutIn:['yard']`)이 0.3초에 걸쳐 낮은 턱으로 가라앉고, 그 벽의
  횃불·깃발(`hideIn`)이 사라진다.

**이 순서가 맞는 조건(= 저작 규칙):** 카메라의 x 는 늘 걷는 통로 안에 있다 · 걷는 바닥보다 높은 `floor` 를 그 앞(카메라 쪽)에 두지 않는다
(두려면 `block`) · 판은 축에 나란하다. 검증 6번이 두 번째를 잡는다.

## 4. 충돌

- 몸 = 발 중앙 `(x, z)` + 높이 `y`, 발 자리 반폭 13 × 7. 발 자리의 땅 높이 = 다섯 점(가운데 + 네 귀) 가운데 가장 높은 곳.
- 이동은 **x, z 를 따로** 해 본다. 새 자리의 땅이 `y + 턱`(땅 위 14, 공중 3)보다 높으면 그 축만 멈춘다 → 벽을 따라 미끄러진다.
- 턱 14 이하는 걸어 오른다(계단 한 칸 12). 더 높으면 점프(높이 ≈ 141, 2단 점프 있음): 단상 72·상자 58 에 뛰어오른다.
- 땅이 발밑에서 사라지면 떨어진다. 구덩이 바닥으로 110 넘게 내려가면 체력 −8, **마지막으로 온전히 딛고 섰던 자리**로 돌아온다.
- 적은 26 넘는 낭떠러지로 내려가지 않는다(넉백 포함). 나는 적(박쥐)은 벽만 막힌다.

## 5. 전투 판정

- 영웅 공격은 v1 `data/movesets.js` 의 채찍 기술을 **그대로** 쓴다: 3연타 = `whip1 → whip2 → whip4(회전 마무리)`, 공중은 `whipA1`.
  판정 시각(`hit`), 상자(`box`: 전방 x · 높이 y), 넉백, 경직, 캔슬 시각 모두 v1 값.
- 깊이는 **얇은 판**으로 본다: `|Δz| ≤ 28`(+4 여유). 높이는 상자 ±18 과 적의 키가 겹쳐야 한다 → 떠 있는 박쥐도 맞고, 단상 위의 적은 아래에서 안 맞는다.
- **조준 도움 2가지** (터치에서 깊이 맞추기가 어려워서): 스틱을 옆으로 밀지 않으면 닿는 거리 안의 가장 가까운 적 쪽을 본다 ·
  앞쪽 닿는 거리 안에서 깊이가 66 까지 어긋난 적이 있으면 휘두르는 동안 그 깊이로 붙는다(깊이 자석).
- 근접 적(해골): 영웅 옆 62 px 자리로 x·z 로 걸어와 깊이를 13 안으로 맞춘 뒤 0.5초 예고(v1 그림의 치켜든 자세 + **발밑 붉은 띠** = 맞는 범위)
  후 휘두른다. 예고 중에 깊이로 비켜서면 빗나간다.
- 원거리 적(박쥐): 거리 255 를 지키며 옆으로 돌다가 0.5초 예고(입가 불빛) 후 탄. 탄은 x·z 로 날고 높이는 영웅 가슴으로 내려오며 땅에 그림자가 있다.
- 공통: 체력, 피격 번쩍임(v1 `flashT`), 넉백, 0.3초 경직, 쓰러짐. 영웅은 피격 무적 0.9초, 대시 무적.

## 6. 카메라

- **횡**: `x` = 영웅 + 보는 쪽 46 px, `z` = 영웅 깊이의 46 %만 따라감, `f 770`.
- **종**: `x` = 통로 가운데 + 영웅 치우침의 50 %, `z` = 영웅 − 64 (영웅이 초점보다 조금 안쪽 → 앞이 더 보인다), `f 600`.
- **모퉁이**: 영웅이 골목 입구 x 범위에 있을 때 깊이 215 → 445 에 걸쳐 두 구도를 부드럽게 섞는다. 카메라는 돌지 않고, 건물 사이로
  보이던 골목 안으로 **앞으로 미끄러져 들어간다**.
- 높이는 `floor` 만 따라간다(단상·상자에 올라서면 영웅이 화면에서 올라간다). 타격·피격 흔들림, 쓰러뜨리면 배율 +3.5 % 튕김.

쓰지 않았다 — 타격 불티·숫자·쓰러짐(기울며 흐려짐)은 `actors.js` 에 작게 다시 만들었다. 본제작에서는 `fx` 를 `World` 에서 떼어 내는 편이 낫다.
영웅은 옆모습 한 장을 좌우로만 뒤집는다(깊이로 걸어도 옆모습) — SLICE0 대로이며, 재디자인 때 앞·뒤 모습이 필요한지는 직접 해 보고 정할 일이다.

## 8. 입체감에 쓴 것과 한계

| 쓴 것 | 효과 | 한계 |
|---|---|---|
| 원근 투영 + 깊이에 따른 크기 | 종 구간이 복도로 보인다 | 카메라가 돌지 못한다(늘 +z). 길이 −z 나 대각선으로 가는 구간은 따로 풀어야 한다 |
| 바닥 윗면 원근 무늬 | 바닥이 실제 면으로 읽힌다 | 띠 두께만큼 세로줄이 톱니가 된다(4 px 띠에서 화면 끝 ≈ 2 px) |
| 단상·상자·계단의 옆면·윗면 | 덩어리감 | 축에 나란한 상자만. 비탈·곡면 없음(비탈은 얇은 계단으로) |
| 깊이 정렬 + 걸어 들어가는 가림막 | 기둥 뒤로 사라짐 | 빌보드는 두께가 없다 → 넓은 소품 옆에서는 어긋날 수 있다 |
| 발밑 그림자(높이에 따라 작고 옅게) | 높이와 깊이를 구분 | 계단 모서리에 걸친 그림자는 한 높이에만 떨어진다 |
| 재질에 구운 안개 + 안개 판 2장 | 멀수록 흐리다. 안개 판은 캐릭터도 흐리게 한다 | 캐릭터 한 명씩 색을 입히지는 못한다(오프스크린 합성이 필요) |
| 먼 배경 시차 · 앞쪽 가림막 · 공기 중 불티 | 걸으면 층마다 다른 속도 | 먼 배경은 한 장 |
| 가로등·횃불 번짐과 바닥 빛 웅덩이 | 깊이마다 빛의 자리 | 진짜 조명이 아니다: 캐릭터는 빛을 받지 않고 그림자는 방향이 없다 |
| 벽 자르기 | 넓은 방에서도 영웅이 보인다 | 저작할 때 어느 벽을 자를지 표시해야 한다 |

Canvas 2D 에서 **안 되는 것**: 원근 변환(텍스처 사영)이 없어 비스듬한 면은 띠로 쪼개야 하고, 깊이 버퍼가 없어 가림은 정렬 순서뿐이며,
픽셀 단위 조명·그림자가 없다. 카메라를 돌리거나(시점 전환) 기울이려면 이 방식으로는 띠 자르기가 성립하지 않는다.

## 9. 프레임 시간

`node tools/v2/proto_a_check.mjs` 의 봇 플레이 전 구간(240틱 창 11–12개)에서 잰 값.

| 화면 | JS (갱신 + 그리기 명령) p50 / p95 | 래스터 포함 p50 / p95 | 캔버스 · 화질 |
|---|---|---|---|
| fold_open 960×726 (봇 플레이 41–49초) | **1.6–1.9 / 2.5–3.4 ms** | 11–12 / 18–20 ms | 1000×756 · 낮음 |
| phone2 1110×540 (봇 플레이 45초) | **1.7–1.9 / 2.9–3.6 ms** | 7.5–9 / 12–15 ms | 740×360 · 낮음 |
| fold_open, 화질 '높음' (서 있는 90프레임, 첫 타일 굽기 포함) | 2.7 / 7.7–10.4 ms | 86–90 / 137–149 ms | 2000×1512 |
| 실시간 루프 (헤드리스, 진짜 터치 시험 중) | 2.0 / 4.0 ms · 59–60 fps | — | 낮음 |

- 그리기 호출: 띠 120–310개, 면 30–40개, 정렬 항목 30–75개. 프레임당 그라데이션 생성 0–2개(구덩이 안벽), `clip` 0–1개.
- **JS 시간은 목표(8 ms)의 1/3** 이다. "래스터 포함"은 그린 뒤 `getImageData` 로 그 프레임의 래스터를 강제로 끝내게 해서 잰 값으로,
  헤드리스의 **소프트웨어 렌더러** 비용이다. 같은 방법으로 v1 본편 `?scene=stage&stage=s01` 을 재면 **낮음 17.6 / 높음 104 ms**,
  v2a 는 같은 자리에서 **7.9 / 99 ms** 였다 — 즉 화면을 채우는 비용은 폴드에서 이미 60 fps 로 도는 v1 본편과 같거나 낮다.
  헤드리스 실시간 루프에서는 59 fps 였다. 그래도 **GPU 가 붙은 실제 폴드에서의 프레임은 이 문서가 증명하지 못한다** — 소유자 기기에서 봐야 한다.
- 싸게 만든 것: 덧칠 제거(안개·밤 빛깔을 타일에 굽기), 하늘 한 장 굽기(기기 px 1:1), `clip` 없는 띠, 낮은 화질에서 굵은 띠·최근접 표본.
- 메모리: 한 판을 끝까지 한 뒤 장면이 만든 캔버스 **115장 15.5 MB**(폴드, 낮음) — 구운 타일(재질·면·안개 단계, 쓰는 것만) 약 95장,
  하늘 1장(3.7 MB, 높음 화질은 최대 8 MB), 소품 13장, 빛·그림자 6장. 장면을 나가면 전부 놓는다(검사 항목).

## 10. 스테이지 한 개를 만드는 비용 · 60개로 늘리기

**저작 (사람 또는 Claude):** 낱말 50–100 줄. SLICE0(횡 2400 + 종 1300 + 마당)이 65줄, 처음 쓰는 데 20분쯤. 검증·봇 플레이로 바로 확인된다.
60 스테이지 ≈ 5,000 줄 데이터.

**그림 (스테이지 묶음 = 테마 하나 기준):**

| 종류 | 장수 | 비고 |
|---|---|---|
| 바닥·벽 타일 (512², 이음매 없음) | 3–5 | v1 `tex/` 20장을 그대로 쓸 수 있다. 밤 빛깔·안개는 코드가 입힌다 |
| 소품 빌보드 (투명 배경) | 8–15 | v1 `props/` 90여 장 재사용 가능. 새 테마면 새로 |
| 먼 배경 1장 | 1 | v1 `bg/` 26장 재사용 가능 |
| 건물 정면 장식 | 0 | 지금은 코드로 그린 창·문·지붕 — 가장 '자리 채우기'로 보이는 부분. 본제작은 정면 그림(앞면에 그대로 붙음)을 테마당 4–6장 |

새 그림이 드는 곳은 정면 장식과 새 테마의 소품뿐이고, 지형 자체(바닥·옆면·계단·구덩이)는 타일만으로 나온다.
캐릭터는 방식과 무관하다(빌보드).

**늘릴 때 필요한 것 (P2):**
1. 저작 낱말을 구간 단위로 올리기 — `street(len, depth)`, `turn()`, `alley(len, width)`, `yard(w, d)` 가 판·벽·구간·카메라 구도를 한 번에 만들게.
   지금은 좌표를 직접 쓴다.
2. 카메라 구도를 구간 데이터로 (지금은 `index.js` 에 SLICE0 좌표가 박혀 있다).
3. 판 조회 가속 — 지금은 판 58장을 매번 훑는다(틱당 약 5천 번 비교, 0.2 ms). 판이 300장을 넘으면 격자 색인.
4. 검증 추가: 카메라 x 가 통로 안에 머무는가, 자를 벽 표시가 빠졌는가(카메라–영웅 사이의 벽 찾기), 적이 화면 밖에서 깨어나는가.
5. 봇 플레이를 스테이지마다 돌려 "끝까지 갈 수 있다"를 자동으로 본다 (지금 검사 스크립트의 봇을 경로 데이터만 바꿔 재사용).

## 11. 위험

1. **실제 기기 성능 미확인.** 헤드리스 숫자는 소프트웨어 렌더러다. 폴드에서 채우기 300–400회/프레임이 60 fps 로 도는지 소유자가 봐야 한다.
   안 나오면: 띠를 굵게(이미 화질 단계로 조절), 벽 옆면을 무늬 대신 단색 + 줄눈 선으로.
2. **카메라가 돌지 못한다.** 길이 되돌아오거나(−z) 대각선으로 가는 구성, 보스전의 시점 전환은 이 방식으로는 안 된다.
   스테이지는 "+x 또는 −x 로 가는 횡"과 "+z 로 가는 종"의 조합으로 한정된다.
3. **옆모습 캐릭터가 깊이로 걷는다.** 종 구간에서 영웅이 옆을 본 채 안쪽으로 걷는다. 재디자인에서 앞·뒤 모습을 그릴지 정해야 한다(방식 B 도 같다).
4. **깊이 조준.** 터치로 깊이를 맞추는 일은 도움(자석·자동 방향) 없이는 답답하다. 지금 값(판 28, 자석 66)은 봇과 키보드로만 맞춰 봤다.
5. **조명이 가짜.** 횃불 옆의 캐릭터가 밝아지지 않는다. 분위기를 조명으로 끌고 가려면 한계가 일찍 온다.
6. **v1 `world.fx` 를 못 썼다** (§7). 타격감의 절반이 거기 있으므로 본제작 전에 떼어 내야 한다.
7. v1 내부 필드 `input._touchVec` 을 읽는다 — 공개 값 `analogX/analogY` 는 8방향 구역에 걸려 대각선이 꺾인다. 공개 접근자를 요청했다
   (`/tmp/claude-0/v2/requests.md`).
