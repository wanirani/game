# SLICE0 — 화면 방식 비교용 시범 구간

시범판 A(`src/v2/a/`, 장면 `v2a`)와 B(`src/v2/b/`, 장면 `v2b`)는 **같은 구간·같은 조작·같은 적**을 서로 다른 화면 방식으로 만든다. 소유자가 폴드에서 둘을 직접 해 보고 고른다. 용어·좌표는 `docs/v2/README.md` §4.

| | 화면 방식 |
|---|---|
| A | Canvas 2D 만 사용. 평행(비스듬한) 투영 + 깊이에 따른 크기·시차·안개로 입체감 |
| B | WebGL 로 세계를 원근 카메라로 그림. 캐릭터는 2D 그림(빌보드) |

## 1. 구간 (위에서 본 평면, 단위 = 논리 px)

1. **횡 구간 — 거리.** x 로 2,400, 걸을 수 있는 깊이 z 0–260.
   - 가로등 또는 기둥 2개: 캐릭터가 뒤로도 앞으로도 지나갈 수 있다 (가림 확인용).
   - 돌 단상: 바닥 300×120, 높이 72. 한쪽에 계단, 나머지는 점프로 오른다.
   - 상자 장애물 1개: 돌아서 지나간다.
   - 구덩이: 깊이의 절반만 막는다. 떨어지면 가장자리에서 다시 시작하고 체력이 조금 깎인다.
2. **모퉁이.** x ≈ 2,400 에서 길이 화면 안쪽으로 90° 꺾인다.
3. **종 구간 — 골목.** z 로 1,300, 걸을 수 있는 폭 x 420. 중간에 오르막 계단(z 200 동안 높이 +96), 양옆에 소품.
4. **마당.** 900×600. 적 5마리를 모두 쓰러뜨리면 "시범 구간 끝" 표시가 뜨고 다시 시작할 수 있다.

## 2. 영웅

- 카엘. 그림은 v1 의 채색 퍼펫(`src/render/hero_puppet.js`)을 옆모습 그대로 쓰고 `facing` 으로 뒤집는다.
- 땅에서 8방향 이동 (위 = 화면 안쪽). 달리기 속도는 v1 과 비슷하게, 깊이 방향은 조금 느리게.
- 점프(중력), 대시(스틱 방향, 없으면 보는 쪽), 검 3연타.
- 공격은 깊이 차이가 작을 때만 맞는다 (|Δz| ≤ 약 28, 조정 가능). 높이도 본다.
- 체력 막대, 피격 무적 시간, 쓰러지면 구간 처음에서 다시.

## 3. 적 (v1 채색 그림 재사용)

- **근접형** (해골·좀비 계열): x·z 로 다가와 깊이를 맞춘 뒤 휘두른다. 휘두르기 전에 예고 동작이 있다.
- **원거리형** (박쥐·술사 계열): 거리를 두고 탄을 쏜다. 탄은 x·z 로 날아가고 땅에 그림자가 있다.
- 공통: 땅 그림자, 체력, 피격 번쩍임, 넉백, 쓰러짐. 길을 따라 모두 8마리 이상 + 마당 5마리.

## 4. 느낌

- 타격 멈춤, 화면 흔들림, 피해 숫자 (v1 도우미를 싸게 쓸 수 있으면 재사용).
- 캐릭터·소품은 깊이 순서로 그린다. 기둥 뒤에 서면 가려진다.
- 카메라: 횡 구간은 x 를 따라가고(z 는 조금), 모퉁이를 부드럽게 돌고, 종 구간은 z 를 따라간다. **입체감이 이 시범판의 목적**이므로 각 방식이 낼 수 있는 것을 다 쓴다.

## 5. 조작

- 터치: 떠 있는 스틱(8방향·아날로그) + 가상 패드의 공격·점프·대시 (`showPad = true`, 안 쓰는 버튼은 `padHideButtons`).
- 키보드·게임패드: v1 바인딩 그대로 (방향 + jump · attack · dash). 일시정지/뒤로 → 타이틀.

## 6. 들어가는 곳 · 검사용 API

- `index.html?scene=v2a` / `?scene=v2b`. `src/v2/<a|b>/index.js` 의 `export default` 가 `Scene` 을 상속한 장면이다.
- `window.__v2 = { id:'a'|'b', hero:{x,y,z,hp}, enemies:[{kind,x,y,z,hp}], cam, section:'street'|'corner'|'alley'|'yard'|'done', stats:{frameMs:{p50,p95}}, teleport(section) }`.

## 7. 그림

- 자리 채우기 그림이면 된다: v1 에셋 재사용, 코드로 그린 질감, 또는 Higgsfield 소량 (바닥·벽 질감, 시범판마다 4 크레딧 이하).
- 다만 **깊이감은 실제로 보여야 한다**: 바닥 윗면, 단상·계단의 옆면, 그림자, 멀수록 흐려지는 색.

## 8. 성능 목표

- 폴드에서 60 fps. 헤드리스 Chromium 기준 프레임 시간 p95 8 ms 이하 (Canvas 2D). WebGL 은 헤드리스가 소프트웨어 렌더러라 대표값이 아니므로 그렇게 적고, 그리기 호출 수·텍스처 메모리를 함께 보고한다.
- 장면을 나가면 만든 캔버스·GL 자원을 모두 놓는다. v1 장면에 영향이 없어야 한다.
