# 채색 보스 파이프라인 (Painted Boss Pipeline) — playbook

Art direction (lead decision): heroes, bosses, enemies, NPCs and companions are **painted cut-out puppets cut from
Kling art, with procedural VFX layered on top**, so the whole cast matches the painted Kling backgrounds and portraits.
This document is the playbook for bosses: the shared runtime (`src/render/painted/kit.js`, `registry.js`), the
build tools (`tools/painted/`), the reference implementation (**Bone Dragon**, `b_bonedragon`), guidance for every
other Part 1 boss and the seven Part 2 bosses, and the budgets / QA rules.
Sister documents: `docs/art/ENEMY_PIPELINE.md` (regular enemies, built on the same `kit.js` primitives),
`docs/art/PUPPET_PIPELINE.md` (hero).

## 1. Architecture

### 1.1 Files

| path | what |
|---|---|
| `src/render/painted/kit.js` | shared runtime: quality flags, texel density + memory budget, render RNG, bake helpers (outline, deep, silhouette, recolour, procedural damage levels with crack-glow overlay), `loadRig` (atlas → baked variants, time-sliced), `Drawer` (one `setTransform` + one `drawImage` per part, flash replay), `Chain`, `ik2`, `Strand` (verlet), `Particles` + `PRESET`, `puff`/`halo`, `DamageState`, `Shards` |
| `src/render/painted/registry.js` | id → renderer module (lazy `import()`), preload on boss-room entry / boss creation, availability check + vector fallback, **culling proxy** entity, boss hooks `paintedTick`/`paintedDraw`, `paintedDebris`, `drawPaintedDirect` (enemies), kill switches, texture release on stage change |
| `src/render/painted/bosses/<id>.js` | one renderer module per painted boss (contract §1.3) |
| `src/game/bosses/a_common.js`, `b_common.js` | the only hooks (3 lines each, §1.2) |
| `assets/painted/bosses/<id>/` | `atlas.webp` + `manifest.json` (generated by `build_parts.py` — never edit by hand) |
| `tools/painted/` | `matte.py`, `build_parts.py`, `grid.py`, `sheet.py`, `build.py` (one command), `poses.mjs` + `poses/<id>.mjs` (pose gallery), `fight.mjs` (real-time full fight), `bench.mjs` (A/B draw cost), `rng.mjs` (gameplay-determinism A/B painted vs vector), `pop.mjs` (bake-vs-appearance timing on a throttled phone), `lib.mjs` |
| `tools/painted/configs/<id>.json` | per-creature build config (cuts, parts, chains, debris, matte, Kling provenance incl. prompts) |
| `tools/painted/raw/<id>/*.webp` | Kling sources (q95 webp, ~10× smaller than the PNG downloads; matting tolerates it) |
| `tools/painted/.work/<id>/` | git-ignored intermediates: mattes, per-part PNGs, grids, parts sheet |

`src/core/assets.js` got one entry: `painted: 'webp'` in the folder→extension map, so atlases load with
`assets.load('painted/bosses/<id>/atlas')`.

### 1.2 Hooks (the whole integration)

```js
// ABoss (a_common.js) and BossB (b_common.js)
init/setup … preloadPainted(this.def.id, this.world.game);   // start baking as early as possible
update(dt, world) { … paintedTick(this, world); }             // attach the culling proxy when the rig is ready
draw(ctx, world) {
  const pd = paintedDraw(this, ctx, world);   // true = painted only · false = vector · 0<k<1 = cross-fade in progress
  if (pd === true) return;
  if (pd) { ctx.save(); ctx.globalAlpha *= 1 - pd; super.draw(ctx, world); ctx.restore(); return; }
  super.draw(ctx, world);
}
```

- **Fallback is automatic**: no module registered, rig still loading, load failed, a draw threw (logged once, entry
  marked failed; the registry calls `st.D.unwind(ctx)` so every `save()`/clip the renderer opened through
  `D.save()` is restored and the canvas state stack stays balanced), or a kill switch is on → the boss draws with its
  existing vector code.
- **No pop when the bake is late.** If the boss was already drawn as vector while its rig was still baking (slow phone),
  the proxy cross-fades vector → painted over 320 ms instead of switching in one frame. The 12 non-painted bosses
  run exactly the code they ran before (verified by `tools/integration.mjs`).
- **The renderer never changes gameplay.** It receives the boss instance and world and only *reads* them
  (animation state, chain points, phase, hp, flash). Hurtboxes, x/y/w/h, timings and RNG are untouched.
- **Culling proxy.** `world.render` culls entities by their rect (`cam.visible(e.x,e.y,e.w,e.h,200)`), and a boss
  rect is only its logic body (the Bone Dragon's is its 88×72 head). A painted boss is much larger (wings, ribcage,
  a neck from a hole 500 px away), so the registry adds one `PaintedBody` entity (`kind: 'painted'`, same `z`, added
  after the boss so draw order is kept) whose rect is `module.bounds()` every frame; it draws the boss and the
  boss's own `draw` becomes a no-op. The proxy dies with the boss, on room reload, on `resetBoss` rebuild, and when
  the painted path is switched off. Debug mode (`?debug`) draws the hurtboxes (cyan) and the cull rect (magenta).
- **Death fade.** `Boss.draw` fades the whole boss from alpha 1→0 over the 2.4 s death. Modules with
  `ownsDeathFade: true` skip that so their breakup stays visible; they fade their own pieces.
- **Debris.** `a_bonedragon.js` asks `paintedDebris(this, i)` first, so the world debris thrown by `ABoss.spawnDebris`
  is painted fragments when the rig is ready (vector bits otherwise).
- Kill switches: URL `?painted=0`, `window.__paintedOff = true`, `settings.painted === false`. Useful for A/B shots.

### 1.3 Renderer module contract

```js
export default {
  id, kind: 'boss', ownsDeathFade: true,
  async load(env)                 // → rig: return kit.loadRig('painted/bosses/<id>', DEF, env). env = {game, td, budgetMB, quality}
  init(boss, rig)                 // → per-instance draw state (particles, strands, damage tracker, per-head caches …)
  draw(ctx, boss, world, rig, st) // world transform already applied; read-only access to boss
  bounds(boss, rig, st, out)      // → {x,y,w,h} covering ALL painted pixels (incl. death debris area)
  lights?(L, boss, rig, st)       // extra lights (added to the boss's own lights)
  debris?(i, rig)                 // → {size, draw(ctx)} painted world-debris piece
}
```
Register it with one line in `registry.js`: `registerPainted('<id>', { kind: 'boss', importer: () => import('./bosses/<id>.js') })`.

### 1.4 Load / bake / memory flow

1. `roomEntered` for a room with `boss: true` **or for the room just before it** (any `exitRight/Left/Up/Down`, `next`
   or `doors` entry that leads to a boss room) → `preloadPainted(id, game, zoom)` (the arena zoom is estimated from the
   boss room height with the same formula as `world.startBoss`). Also called from boss `init` (boss rush, retries).
   Measured on an emulated mid-range phone (CPU ×5 throttle, 844×390): the bake takes ≈5 s of wall clock while the
   player fights through the antechamber, so it is ready long before the arena trigger; started only at the boss-room
   door it finished ≈1.5 s after the boss appeared (→ the cross-fade above). `node tools/painted/pop.mjs <id> --mobile
   --cpu 5 [--from ante|boss]` measures this.
2. The module is `import()`ed, `manifest.json` fetched, the atlas loaded through `assets.js`.
3. `loadRig` picks the **texel density** `td = canvas scale × arena zoom × 1.1 × quality.tdMul` (clamped 0.7…2, and
   ≤ the atlas td) and caps it at `tdMax`, the highest density whose estimated baked memory fits 97 % of the budget
   (**15 MB desktop, 6 MB phone or quality low**; the estimate counts every variant incl. tint crack-glow overlays —
   before the review it under-counted and desktop landed at 15.4 MB). With a phone budget the middle damage level is
   skipped (dmg1 falls back to base, and no crack glow is drawn at level 1 — the glow must match the cracks drawn).
   The rig keeps `td`, `tdMax`, `tdReq`, `budgetMB`.
4. Per part: scaled copy → outline (thin dark rim, 12-tap) → damage 1 and 2 (cumulative) + half-res crack-glow
   overlays → flash/glow silhouettes (flash parts) → darkened "deep" variant (far limbs / body mass) → tints
   (e.g. the twin's frost). Work is time-sliced (`nextIdle`, 8 ms slices via MessageChannel — not
   `requestIdleCallback`, which waits for its timeout while the game loop is busy).
5. All bake canvases are CPU canvases (`willReadFrequently`). On GPU-backed canvases every `getImageData`/copy is a
   GPU read-back: under SwiftShader the Bone Dragon bake took **25 s** that way vs **< 1 s** now. Finished variants
   are frozen to `ImageBitmap` (uploaded to the GPU once, no per-frame re-upload).
6. The atlas image is dropped from the assets cache after baking. When the player enters a stage whose boss is
   different, the baked rig is released (`stageEntered`).
7. **Re-bake when the screen changed** (`refreshPainted`): on room entry, if the density the screen now wants
   (capped by `tdMax`) differs from the baked one by > 25 %, or the rig exceeds a smaller budget (auto quality drop), the
   rig is re-baked in the background and swapped in when ready (the old rig keeps drawing, no pop). During a fight
   only growth > 40 % (window → fullscreen) triggers it — never a shrink, so a slow phone that just dropped quality is
   not given extra bake work mid-fight. Renderers must not cache texel-space data across rigs (`st.rig !== rig` → reset,
   e.g. the dragon's mouth gradient).

Measured bake (headless Chromium, loaded machine): desktop 2560×1440 td 1.40 → 15.4 MB, 1.8–2.5 s wall clock of
which ~0.6 s is work and the rest yields to game frames; phone 844×390 (medium) td 0.80 → 4.2 MB, 0.5 s. All of it
happens behind the boss-room fade / pre-fight dialogue / boss intro (≥ 3.6 s).

## 2. Playbook: making a boss painted (step by step)

1. **Read the logic first.** List every state (`s_<name>` / `setState(...)`), phase transform, death, and the fields the
   draw code reads (for the Bone Dragon: `Wyrm.pts/k/hole/hx/hy/a/jaw/flare/wing/ext/hidden`, `boss.fury/phase/twin/deathT`).
   Write `tools/painted/poses/<id>.mjs` (`STAGE`, `POSES`, `INSTALL`, `BENCH`) before any art: a pose per state,
   windup and active frame, hit, each damage level, each phase transition, death at 4–5 times. Run
   `node tools/painted/poses.mjs <id> --vector` once — that is the "before" sheet.
2. **Plan the rig** (§6 gives the plan for every existing boss): which parts are rigid sprites, which are chains of tiles,
   which are procedural (cloth, hair, tentacles, strands, fire, fluids), which parts need a hinge cut (jaw, visor,
   book cover), which need variants (second form, twin, elite palette → a baked tint, not new art).
   Budget: ≤ 40 parts, atlas ≤ 2048², ~10–20 Kling images.
3. **Generate with Kling** (§3 templates): `image_to_image`, `kling-image-v3_0_omni`, 2k, the boss portrait
   (`assets/portraits/<id>.webp`) as `图片1`; for repaints of an existing part add that part as `图片2`. One shot per
   part group. Download with `curl`, convert to `tools/painted/raw/<id>/<name>.webp` (quality 95), and log prompt +
   generation id + keep/reject reason (rejected calls too) in the config's `kling` block. Mechanics (verified in the
   review):
   - Load the tools with ToolSearch `kling`, call `who_am_i` with `tools: ["image_to_image"]` first (it lists the
     argument names: `prompt`, `img_resolution`, `aspect_ratio`, `imageCount`; inputs `image_1`…`image_10`).
   - Reference images must be **uploaded**: only PNG/JPG, so convert the webp portrait first
     (`python3 -c "from PIL import Image; Image.open('assets/portraits/<id>.webp').convert('RGB').save('/tmp/p.png')"`),
     call `file_upload` (content type, file name, byte size) → a single-use ticket, then
     `curl -X POST https://kling.ai/api/mcp/files -F ticket=<ticket> -F "file=@/tmp/p.png;type=image/png"` → `data.url`.
     Pass it as `{name: 'image_1', inputType: 'URL', url}`. Reuse the URL for further calls.
   - `image_to_image` returns a generation id; poll `query_tasks` (≈50–60 s for 2 images at 2k). Result URLs expire
     after 24 h — download immediately. The bottom-right "KlingAI 3.0 Omni" mark is removed by `matte.py`.
   - `imageCount: 2` costs two images but usually saves a retry; budget the rejects (the review needed 3 calls for 1 part).
4. **Author the config** `tools/painted/configs/<id>.json`. Use the grid helper for every coordinate:
   `python3 tools/painted/grid.py <id> <src> [x0 y0 x1 y1] --step 50 [--scale 0.5] [--matte]` — it overlays the config's
   boxes, pivots, point lists, mask/punch polygons, chain joints and debris boxes on the source, so you iterate by
   editing JSON and re-running. For chains, find the joints automatically (dark-gap profile, see §5.2) and check them
   on the grid.
5. **Build**: `python3 tools/painted/build.py <id>` (matte is cached; `--force` recomputes). Review
   `.work/<id>/parts_sheet.png` (two-tone background shows grey fringes on the dark half and dark halos on the magenta
   half; cyan dots are pivots).
6. **Write the renderer** `src/render/painted/bosses/<id>.js` with `kit.js` (§4), register it, and keep the rules of §8.
   Every new part is baked with the defaults (outline + damage 1/2 + crack glow + every tint) unless its name or prefix
   is listed in the renderer's `DEF`: give props/debris/terrain `noDmg: true` (⅓ of the memory) and decide per tint
   whether the part is recoloured (`skip: [...]`) — the dragon's rim is tinted so the twin's hole burns blue, its debris
   is not. Adding a part (review exercise, 1 part): raw → config `parts[]` entry (box, `lps` from the wanted in-game
   width ÷ source width, pivots) → `grid.py --matte` → `build.py` (≈40 s, matte cached) → `DEF` entry → draw call →
   pose sheet. `build_parts.py` writes `atlas.hash` into the manifest and the runtime appends it to the atlas URL, so
   a rebuilt atlas can never be paired with a stale cached manifest.
7. **Verify** (all must pass, §9):
   `node tools/painted/poses.mjs <id>` (+ `--mobile`, `--debug`), `node tools/painted/fight.mjs <id>` (+ `--mobile`),
   `node tools/painted/bench.mjs <id> --dpr 1|2|--mobile`, and
   `node tools/integration.mjs --only <stage>_boss,…` (no page errors). Compare against `--vector` sheets.

## 3. Kling prompt templates (what worked)

Model `kling-image-v3_0_omni`, tool `image_to_image`, `img_resolution: 2k`, `imageCount: 1–2`.
Reference `图片1` = the boss portrait (style, palette, anatomy). `图片2` = an already-kept part (material/layout)
only when you want a sibling part to match it closely. Always end with the **common suffix**:

> Flat uniform plain mid-grey studio background (#808080), no gradient, no floor, no cast shadow on the background.
> Strong key light from the upper left, darker lower right, crisp readable silhouette. Isolated object, nothing else in
> the image, no text, no labels.

Why each rule matters: flat mid-grey = `matte.py` keys it perfectly and punches holes (torn membranes) that rembg
alone misses; upper-left key light on *every* part = the assembled puppet is lit consistently (never mirror a part
whose light direction matters without accepting the flipped light); side view = puppets are 2D; one part group per
image = cut lines stay simple; the watermark (bottom-right) is removed automatically, keep objects away from that
corner.

| shot | aspect | template (prefix + common suffix) | notes |
|---|---|---|---|
| head / skull with hinge | 4:3 | "Game asset sheet for a 2D cut-out puppet. Strict side view (profile) of the head of 图片1 facing right, **mouth wide open** showing both rows of teeth and the dark throat, the lower jaw clearly separate at the hinge, …" | open mouth is mandatory for a jaw cut: the dark throat is punched transparent (`punch: dark`) and a procedural mouth interior is drawn behind the jaw |
| straight chain (neck, tail, tentacle, spine, whip) | 21:9 | "…a single **straight horizontal** chain of N separate … joined end to end, strict side view, perfectly straight and level, runs left to right across the whole image with empty margin at both ends, head side on the right, … clear separation between each segment" | never curved: tiles are cut between joints. With `图片2` = an existing chain the model copies it closely → you get a repaint (new cracks/sinew per tile), not new shapes; get shape variety by splitting spines (`splitSpines`) and runtime jitter |
| torso / body mass | 3:4 | "…the ribcage/torso of 图片1 alone, rearing, side view, the neck socket at the top left, the stump of the body at the bottom, soul fire inside…" | pivots: neck socket, shoulders near/far, core, hips |
| single wing / limb | 4:3 or 1:1 | "…a single left wing of 图片1 spread wide, root at the lower left, fingers fanning to the upper right, torn membrane with holes…" / "…a single foreleg, elbow at upper left, claws planted flat at lower right…" | draw both sides from one sprite (mirror + deep variant for the far side) |
| debris / fragments | 16:9 | "…N separate broken fragments of 图片1 … arranged in a loose grid with wide empty space between pieces, no piece touches another…" | cut with `debris.boxes`; used for death breakup, hit chips and rubble mounds |
| armour plates / mechanical | 4:3 | "…the separate armour pieces of 图片1 laid out apart from each other: helm with visor raised, breastplate, pauldron, gauntlet (open hand), greave…" | one plate per piece, hinge pieces (visor, jaw, covers) open |
| cloth / hair texture swatch | 1:1 | "…a flat rectangular swatch of the gown fabric of 图片1, seen straight on, evenly lit, no folds, tileable…" | used as a pattern on procedural cloth (§6.4); matting not needed |
| ground rim / burrow lip (review) | 21:9 | "Paint in exactly the same painterly dark-fantasy oil-painting style as 图片1: soft visible brush strokes, … no black outlines, not cartoon, not cel-shaded, not 3D render. Subject: … a single low wide heap of rubble that forms the torn rim of a hole in a catacomb floor, seen strictly from the side at ground level: broken grey flagstone slabs tilted up, dark earth, old skulls and snapped bones half buried … **No dragon, no spine, no vertebrae, no chain.** … bottom edge flat and horizontal, about five times wider than tall, a bit taller at both ends and lower in the middle…" (full text in `configs/b_bonedragon.json` → `kling.images.rim_a`) | portrait only as reference. Pivot `c` = bottom centre; crop the soft ground shadow off with the box |
| second form / palette | — | **don't**: bake a tint (`kit.RECOLOR`, per-material HSL rules) unless the silhouette changes | the Bone Dragon twin is a frost tint of the same parts |

**Reference-image rules learned in the review** (3 calls for one part):
- `图片2` must be a *painted* asset in the target style. A photographic / tileable texture (tried: `assets/tex/tex_bone`)
  pulled both results into paper-craft and cartoon-sticker styles with thick outlines.
- The model copies the *content* of `图片2`, not only its material: with the debris sheet (which contains a vertebra
  chain) both results were a vertebra chain lying on rocks. When the new part must not look like the sibling sheet, pass
  the portrait alone and say what must *not* appear ("no spine, no vertebrae, no chain").
- Lead with the style clause ("exactly the same painterly … as 图片1 … no outlines, not cartoon") — the "game asset"
  wording alone drifts toward clean cel-shaded sticker art.

Cost reference: Bone Dragon = 11 images in the prototype (skull ×2, torso, wing ×2, leg, chain ×2, vertebra sheets ×2,
full body) + 3 here (chain repaint ×2, debris ×1). Budget per boss: 10–20 images.

## 4. `kit.js` in one page

```js
import { loadRig, pickVariant, Drawer, Chain, ik2, Strand, drawStrand, Particles, PRESET, DamageState, Shards,
         halo, puff, rr, hash1, quality, RECOLOR } from '../kit.js';
const rig = await loadRig('painted/bosses/<id>', {
  glow: '#7dff9a',                                  // crack-glow / glow-silhouette colour
  outline: { width: 2.2 },
  parts:  { skull: { flash: true, cracks: 4 }, wing: { deep: 0.74, deepOnly: true, membrane: true } },
  prefix: { va: { cracks: 2, char: 1 }, deb: { noDmg: true } },   // options by name prefix
  tints:  { frost: { rules: 'frost', levels: ['dmg2'], glow: '#8ac8ff', skip: ['deb'] } },
}, env);
const img = pickVariant(part, level /*0..2*/, deep /*far/body mass*/, tint /*'frost'|null*/);
D.begin(ctx); D.part(part, img, 'pivotName' | [x,y], worldX, worldY, rot, sx, sy, alpha); D.end();
D.pt(px,py, qx,qy, x,y,rot,sx,sy, out)  // where texel q of a part placed like that lands in the world
D.rec = true → D.part logs flashable parts → D.flash(alpha) replays white silhouettes additively (hit flash)
```
- `sx/sy` are world px per texel: `part.k * scale`, negative = mirror. Pivots are in baked texels (pad included).
- `Chain.set(points, k)` → `arc[]` (distance from the root), `at(d)`, `frames()` → per segment `{x,y,a,len,bend,turn}`.
- `ik2(sx,sy, tx,ty, l1,l2, bend)` → elbow + angles (two-bone limbs).
- `Strand` = verlet rope (`pinB` for sagging sinew between two anchors); re-hangs itself if an anchor teleports.
- `Particles` (pooled, struct-of-arrays, batched by preset/colour): `ash ashLight ember boneDust smoke spore spark
  ichor blood splat chip`; `ichor`/`blood` drops hang (`hang` s), fall and leave floor splats; `chip` bounces.
- `DamageState([0.6,0.3])` → level 0..2, `update(ratio)` returns the new level only on the frame it rises (burst there).
- `Shards` = rigid painted pieces for death breakups (gravity, floor bounce, rest, fade).
- `halo(ctx,x,y,r,color,a,core)` = additive cached puff sprite — **the** glow primitive (no gradients per frame).
- `rr` = render-only RNG (`next/range/chance/sign`), `hash1(i)` deterministic noise.
- `D.save()` / `D.restore()` — use these (not `ctx.save/restore`) around clips; the Drawer counts the depth so the
  registry can `D.unwind(ctx)` after a draw error.
- `Shards.draw(D, sink = 6)` clips at the floor line (+sink) so long rotated pieces (legs, vertebrae) look half buried
  instead of lying on top of the floor tiles.
- `ledgesOver(ctx, world, x0, y0, x1, y1)` re-draws the one-way ledge planks (copied from the tile chunk canvases, one
  `drawImage` per run) inside a world rect. Tiles are drawn before entities, so a big opaque painted body hides the
  ledges the player must jump to; call it after the body's back layer, before the head/neck (§8.11).
- `QUALITY.*.flames` (flame puffs per soul-flame tongue, 5/4/2), `.tube` (spinal-tube strokes 2/2/1), `.ledges`.

## 5. Reference implementation: Bone Dragon (`b_bonedragon`)

### 5.1 Parts (atlas 2048×1001, 390 KB webp, td 2.0)

| group | parts | source | notes |
|---|---|---|---|
| skull | `skull_upper`, `skull_jaw` | `skull_a` (mouth open) | jaw = polygon mask minus red horn pixels; dark throat punched; mouth lines `mouthUpper/mouthLower` feed the procedural mouth interior |
| body | `torso`, `wing`, `leg` | `torso_a`, `wing_b`, `leg_a` | wing/torso baked `deep` only; far wing = same sprite mirrored + scaled 0.86; far leg = deep variant |
| neck bodies | `va0…va5`, `vb0…vb5` (12) | `chain_a`, `chain_c2` | tiles between joints; long ichor strings trimmed (`trimDrips`) — drips are particles now, falling world-down |
| dorsal spines | `vas0…`, `vbs0…` (12) | same chains | `splitSpines`: cut above `top`, 26 px overlap hidden behind the body; placed at each tile's `spn` anchor |
| debris | `deb0…deb6` | `debris_a` | death breakup, world debris, fallback rubble when there is no rim |
| rim | `rim` | `rim_a` (review) | painted burrow lip in front of every hole (floor, wall — rotated, clipped at the floor) and flattened at old-hole scars; frost-tinted for the twin; covers the ribcage's floor clip line |

Baked (desktop): base + dmg1 + dmg2 per part, crack-glow overlays, flash/glow silhouettes for skull+jaw, frost tint of
dmg2 for everything but debris → **14.1 MB at td 1.33** (budget-capped); phone budget → td 0.80, no dmg1 → **4.2 MB**.

### 5.2 How each logic state reads (all states in `a_bonedragon.js` are covered)

| state / event | painted result |
|---|---|
| idle | ribcage breathing, slow wing flap, jaw idle, soul fire in ribcage/eyes, ichor drips from the neck underside, verlet sinew swaying. The body turns (paper flip ≈ 0.3 s) only when the head crosses the hole by more than 56·s px — with the player standing on the hole it used to flip every ~3.5 s |
| bite (windup/lunge) | neck reared (logic), jaw open with sticky ichor strands, lunge smear (additive glow silhouettes of the skull), bone dust |
| breath | mouth fire (flame puffs) + embers streaming along the head angle; projectiles are still the logic's |
| boneRain / transform | wings fully open + fast flap, crack glow ×1.8 during transform, head-up flip hysteresis (no flicker at vertical) |
| spit | jaw open, mouth glow |
| burrow (dive → eruption) | neck retracts into the hole, torso sinks below the floor line (clip + pit shadow + painted rim); new hole: eruption burst (chips, dust, ichor, embers along the hole normal); the old hole leaves one crater scar (flattened rim) that fades. ### 5.3 Prototype cons and how they were fixed

- **Vertebra joint gaps on tight bends** → (1) a spinal "sinew tube" (two strokes, dark flesh) is drawn under the
  tiles along the chain, so the outer side of a tight bend shows anatomy instead of background; (2) tile overlap grows
  with the bend angle (`1.22 + bend·0.55`); (3) soul-fire halos in the joints.
- **Repetitive tiles** → 12 body tiles from two chain paintings + 12 separately cut dorsal spines, chosen by long
  non-repeating permutations (`seq`), different for main and twin; each spine gets its own scale (0.78–1.2), angle
  jitter and a 14 % chance of being a snapped stub; per-instance damage/glow on every third tile.
- **Death breakup not visible** → `ownsDeathFade` (no global fade) and a real breakup into `Shards`.
- **Muddy twin recolour** → the old tint pushed every pixel toward grey-blue. `kit.RECOLOR.frost` maps materials
  separately in HSL (soul green → icy blue, rotten flesh → deep violet, bone → pale cool ivory, shadows → blue-black),
  the crack-glow overlays are recoloured too, and the char in damage bakes is softer (heavy char was the other source
  of mud). The twin now reads as a distinct frost dragon.
- Also fixed: gameplay `Math.random` / `world.fx.emit` in draw code (render RNG + own particle pool only; `fx.ring`
  is RNG-free and allowed), lazily baked twin tint (now baked at load, no hitch), `requestIdleCallback` baking stalls,
  GPU read-back during bake, per-frame gradient/array allocations.

### 5.4 Hurtbox and cull notes (documented, gameplay NOT changed)

- Head hurtbox (`Wyrm.box()`): 88×72 centred on `(hx,hy)`, not rotated. The painted cranium spans about
  −65…+80 px along the head axis and −30…+44 px across (jaw closed; horns excluded). The snout tip (≈36 px) and the
  back of the skull (≈21 px) are outside the box, so a hit on the snout whiffs. **This is not a regression**: the vector
  skull (`skull()` in `a_bonedragon.js`, scale 1.12) reaches −51…+78 px, i.e. the same snout overhang; the painted one
  only adds ≈14 px at the back plus the horns.
  **Recommendation** (needs a gameplay owner's sign-off): `w 128·s, h 76·s`, centre shifted 10·s along the head
  direction (`hx + cos(a)·10·s`), or two boxes (cranium 90×70 + snout 50×40 rotated with `a`). Contact/bite damage uses
  the same box, so widening it also makes bites reach ~20 px further — re-tune `strikeRect` knockback if you change it.
- Neck, wings, ribcage and legs have no hurtbox (as before): the player can stand "inside" the painted body without
  contact damage. That is intentional in the logic (only the head hits/is hit); keep telegraphs readable because the
  painted body is visually much bigger than the vector one.
- Cull rect (`bounds`): hole ±380·s (lifted 200·s for floor holes), every chain point ±110·s, the skull ±190·s, and the
  whole arena floor band while dying (shards). Verified with `?debug` (magenta dashed rect).

## 8. Budgets and performance rules

1. **Memory**: ≤ 15 MB baked per boss on desktop, ≤ 6 MB on phones/low quality (enforced by `loadRig`; check
   `window.__painted[id].memMB`). Atlas ≤ 2048×2048, webp q90, ideally < 600 KB. One boss rig resident at a time
   (released on stage change).
2. **Bake**: only behind the boss-room fade / dialogue / intro (`preloadPainted`), never on the first fight frame;
   time-sliced; no bake work at phase changes (bake tints at load). Keep total bake work < 1 s desktop.
3. **Per frame**: ≤ ~90 part draws (`D.part`) per boss, ≤ 15 additive halos, ≤ 12 crack-glow overlays, particle pool
   ≤ 420 (high) / 260 (medium) / 120 (low). No `ctx.save/restore` per part (use `Drawer`), no gradient creation per
   frame (cache them in part texel space or use `puff`), no `shadowBlur`, no `filter`, no per-frame arrays/objects
   in hot loops (pool them in the per-instance state).
4. **Smoothing**: set `ctx.imageSmoothingQuality = 'low'` while drawing baked sprites (they are baked near device
   resolution; 'high' is very slow on big sprites) and restore it.
5. **Determinism**: draw code must not call `Math.random`, `rand()`, or `world.fx.emit/burst` (they consume the
   gameplay RNG). Use `rr`, `hash1`, the module's own `Particles`. `world.fx.ring/flash` are RNG-free.
6. **Simulation in draw**: particles, strands and shards advance with `world.time` deltas (clamped to 50 ms). They
   pause during hitstop (correct) and advance only when drawn — capture harnesses must render every stepped frame.
7. **Culling**: `bounds()` must cover every painted pixel (wings, off-screen chain, death debris); verify with
   `?debug`. Never enlarge the logic rect to fix culling.
8. **Hurtboxes**: art that grows beyond the logic boxes is documented (like §5.4), not silently "fixed" in logic.
9. **Quality flags** (`kit.QUALITY`): `high` everything; `medium` fewer particles/strands, no strand highlight;
   `low` no halos, no strands (static curves), no crack glow, no smear, fewer particles, td ×0.75 (and the 6 MB budget).
   The renderer follows the setting live (the game lowers quality automatically on slow touch devices).
10. **Fallback must stay working**: every boss must still be fully playable with `?painted=0`.
11. **Arena ledges stay readable**: a painted body that covers one-way ledges must re-draw them (`ledgesOver`) between
    its back layer (body, wings, limbs) and its front layer (neck, head, attack parts). Split the renderer into
    prepare → back → ledges → front passes (the dragon's `prepHead/backHead/frontHead`).
12. **Nothing below the floor**: clip every body/limb/rubble layer at the arena floor (+2 px), also for wall holes and
    death shards. Parts pushing through the floor tiles read as a rendering bug.
13. **Telegraph-driven positions leave no trails**: when the logic moves an anchor every frame during a warning (the
    burrow hole follows the player), effects keyed to "anchor moved" (scars, bursts, strand resets) must wait until the
    anchor was actually used.
14. **Facing needs hysteresis** when it is derived from a position difference that can hover around zero.
15. **Cull bounds include lingering effects** (scars far from the current hole, ash spawned above the head, shards).

## 10. Known limitations / next steps

- Hurtbox widening for the Bone Dragon head is a recommendation only (§5.4) — needs a gameplay decision.
- The vector wall-hole/burrow rubble of other bosses is untouched; the dragon's holes use the painted rim (§5.1).
- Phase transitions: `ABoss.phaseBurst` calls `camera.punchZoom(1.08)` and the arena camera then frames the player,
  so during the Bone Dragon's transform (and the twin's arrival) the dragon is often off-screen — vector and painted
  alike. A camera/gameplay decision (e.g. punch-zoom toward the boss), not a renderer issue.
- Boss rush / arcade (`src/scenes/front/arcade_run.js`) spawns bosses directly in the arena (no `roomEntered`), so the
  bake starts at boss `init` and runs during the ≈3.8 s intro; on a slow phone it can finish after the intro starts
  (the cross-fade hides the switch). Recommendation for the arcade owner: call
  `preloadPainted(queue[round + 1], game)` when a round starts. The registry now keeps at most one boss rig resident
  (a boss rig not drawn for 2 s is released when another boss starts baking), so rounds do not accumulate memory.
- On phones the right-hand touch buttons sit over the dragon's hole/ribcage (HUD layout, not the renderer); the head
  and every telegraph stay visible.
- The painted jaw still carries its painted ichor drips; they rotate with the head (point sideways when the head aims
  down during the breath). Trimming them like the chain drips (`trimDrips`) would need a skull re-cut.
- Headless measurements are CPU-bound and noisy (other agents share the machine); re-run `bench.mjs --gpu` on a real
  GPU machine for release numbers.
- Enemy renderers (`docs/art/ENEMY_PIPELINE.md`) share `kit.js` primitives but use their own `enemy_kit.js` drawing
  layer; keep `kit.js` exports backward compatible (`makeCanvas`, `outlined`, `silhouette`, `darkened`, `bakeDamage`,
  `rr`, `hash1`, `seeded`, `textureDensity`, `nextIdle`, `sliceStart`, `quality` are imported there).
